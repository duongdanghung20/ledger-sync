# Ledger-Sync v1 — chart the way to a buildable spec

Labels: wayfinder:map

## Destination

A buildable v1 spec for Ledger-Sync: enough decisions locked (CSV import, categorization, double-entry journal, QBO sync, auth) to hand to `/to-spec` → `/to-tickets` → `/implement`. Single-tenant, multi-user, Organization-scoped, self-hosted via Docker Compose. This map produces decisions, not code.

## Notes

- **Domain**: double-entry bookkeeping + QuickBooks Online sync. Read `CONTEXT.md`; use its vocabulary in every ticket, title, and decision.
- **Skills every session consults**: `grilling` + `domain-modeling` for HITL decision tickets; `ponytail` for any code written; `frontend-design` for UI tickets (see ticket 09); Context7 for all library/framework/API docs (Next.js, FastAPI, psycopg, QuickBooks Online API) — never from memory. CodeGraph: repo not yet indexed, use normal file tools.
- **Standing preference**: the money path — double-entry balancing, idempotent QBO push, CSV dedup — is held to a correctness bar and never simplified away. Everything else follows the ladder.
- **Framing decisions accepted at charting** (grilling Q1–Q11, Q2a–e):
  - Destination is a spec handoff; wayfinder plans, does not build.
  - Single-tenant, multi-user, Organization-scoped, RBAC = Admin + Bookkeeper, admin-invite only (ADR-0001).
  - **Book** is a first-class object and the boundary for all financial data: an Organization owns one or more Books, each mapping to one QuickBooks company (`realmID`) with its own Chart of Accounts and Bank Accounts (ADR-0003). v1 auto-creates one Book per Organization; multi-Book UI deferred. Roles stay Organization-wide.
  - **Bank Account** is first-class, Book-scoped; every Imported Transaction carries its source Bank Account.
  - Real tool: money-path correctness matters.
  - QuickBooks Online is the source of truth for the Chart of Accounts, **per Book** (ADR-0002).
  - Categorization is rules-based + manual override; ML deferred.
  - QBO integration v1: read each Book's Chart of Accounts down + push Journal Entries up to that Book's company; per-entry Sync Status + idempotent retry (`requestid` + `DocNumber`, ticket 01).
  - CSV import: arbitrary CSV + saved Column-Mapping Profile per bank + dedup by hash.
  - Docker Compose packaging in scope; CI/CD out.

## Decisions so far

<!-- index of closed tickets: one line each, gist + link. -->

- [QBO API research](issues/01-qbo-api-research.md): `JournalEntry` = the object for arbitrary debit/credit lines (min 2, debits=credits, positive amounts + `PostingType`); native idempotency via `requestid` param (back with `DocNumber`/`PrivateNote` + query-before-retry); OAuth per-company, one token set per `realmId`, one app holds many concurrently; `Account` soft-deleted via `Active` (query `Active IN (true,false)`); 500 req/min + 10/s per realm, batch ≤30. Full findings: [`research/qbo-integration.md`](research/qbo-integration.md).
- [QBO connection and credential storage](issues/02-qbo-connection-credentials.md): one QuickBooks Connection per Book (`realmId`-scoped); in-app OAuth2 auth-code, Admin-only, self-serve reconnect; app `client_id`/`secret` via env (one Intuit app per instance, many `realmId`s), never DB; per-Book tokens in Postgres, refresh token encrypted at rest with env `TOKEN_ENC_KEY` (Fernet/AES-GCM); on-demand refresh with atomic persist of the rotated refresh token, failure → status `disconnected` + Admin reconnect; redirect URI `{APP_BASE_URL}/api/qbo/callback`. Env: `QBO_CLIENT_ID`/`QBO_CLIENT_SECRET`/`TOKEN_ENC_KEY`/`APP_BASE_URL`.
- [Categorization rule engine](issues/04-categorization-rule-engine.md): a Categorization Rule = ordered conditions (AND within a rule; OR = a second rule) → one target Account (Active, excl. AR/AP per 03). Fields payee/description/amount/date; ops contains/equals (text, case-insensitive), gte/lte/between (amount/date). **First-match-wins by priority** → exactly one Account per txn (clean counter-side for 06). Rulings: amount matches the **signed** canonical amount (`≤ -100` = $100+ outflow, not magnitude); conflict = **silent** priority tiebreak (no "also matched"); manual override sets Account on the one txn, **beats rules + survives re-run**, "make a rule" deferred. Unmatched → `uncategorized` → manual. Records source (`rule`/`manual`/`none`) + matched rule for review UI (09). Liftable pure engine + prototype: [`04-categorization-prototype.html`](issues/04-categorization-prototype.html).
- [Chart of Accounts sync](issues/03-chart-of-accounts-sync.md): read-only per-Book mirror (v1 never writes `Account` back). Refresh on connect + manual "Refresh" + lazy auto-refresh before review/push; no scheduler; per-Book `last_synced_at`. Full mirror incl. inactive (`Active IN (true,false)`); cache `qbo_id`/`Name`/`AccountType`/`AccountSubType`/`Classification`/`AcctNum`/`Active`/`SyncToken`/`parent_qbo_id`; reconcile = upsert by `qbo_id`, absent → `Active=false`, never hard-delete. Categorization targets (feeds 04) = all `Active` accounts, no Classification restriction, grouped by Classification; exclude inactive from new picks + exclude AR/AP (need `Entity`). Dangling refs: invalid rule kept+flagged+skipped→manual; un-pushed txn on inactive account blocked from batch + flagged, rest posts (enforced at push, ticket 08).
- [CSV import, column mapping, dedup](issues/05-csv-import-column-mapping-dedup.md): canonical Imported Transaction = `date`(ISO)/signed `amount`(**neg=out**, matches 04)/`description`/opt `payee`/opt `external_id`, scoped to Book+Bank Account. Column-Mapping Profile = per-bank/per-Book JSON (delimiter, decimal dot/comma, date format, `signed`{flip} vs `debit_credit` amount modes, column map); auto-suggested by CSV header signature. Bank Account chosen at import (profile default, override/create inline); **dedup scoped per Bank Account**. **Dedup ruling**: bank unique id → dedup on `external_id` alone (bulletproof); else `hash(date,amount,description,payee)` reconciled as a **multiset** (dup only if an existing unmatched row shares key; extras are new) → never double-imports, never drops same-day identicals; surface "N possible dupes in file" not silent guess. Ceiling (`ponytail:`): no unique id → non-aligned re-import windows ambiguous, opt. running-balance as extra key. Malformed rows → rejected list w/ reason, never imported/silently dropped. Backend uses Python stdlib `csv`. Real-sample validation deferred to build. Prototype + headless check (7/7): [`05-csv-import-prototype.html`](issues/05-csv-import-prototype.html).
- [Authentication and RBAC](issues/07-auth-rbac.md): local passwords (**Argon2id**, min 12, no rotation, no HIBP), **no external IdP** (ADR-0004); **httpOnly session cookie, sessions in Postgres** (revocable on disable/role-change, 14d absolute expiry) over JWT, same-origin behind `APP_BASE_URL`. Two Organization-wide roles, **Admin ⊇ Bookkeeper**; Admin-only = QBO Connection, User management, Bank Account create+`qbo_account_id` mapping; everything else (import, categorize, refresh CoA, review/approve/push) shared. Enforced server-side per FastAPI route, frontend never trusted. **No email v1**: one set-password link primitive (signed, expiring, single-use), Admin delivers out-of-band; reset = same primitive, Admin-triggered. New term **Invitation**. **Bootstrap**: `BOOTSTRAP_ADMIN_EMAIL` env → first boot creates Org + auto Book (ADR-0003) + Admin, set-password link printed to container logs; no password in env, no open setup screen. New env: `BOOTSTRAP_ADMIN_EMAIL`, optional `ORG_NAME`, `SESSION_SECRET`. New tables: `User`/`Session`/`Invitation`.
- [Sync status and idempotent QBO push](issues/08-sync-status-idempotent-push.md): approved Journal Entries pushed **one per call, synchronously** (no `batch`, no worker); idempotency = stable per-JE `requestid` (UUID minted at approval, reused, **never regenerated**) + `DocNumber`=JE id + query-before-retry on 5xx/network → **retry never double-posts** ([ADR-0005](../../docs/adr/0005-idempotent-journal-entry-push.md)). Sync Status kept {pending,posted,failed} (no glossary change); concurrency via per-Book push lock; crash mid-push stays `pending`, recovered by query-before-retry. Retry = manual re-push of `failed`; `4xx`→failed+reason, `5xx`/network→query-by-`DocNumber` then posted/failed, `429`→stop+leave `pending`; pre-push validation (inactive Account/unmapped Bank Account, per 03/06) skips entry + continues. Error data: `last_error`/`last_error_code`/`last_attempt_at`/`attempt_count`; display is 09's.
- [Double-entry journal model](issues/06-double-entry-journal-model.md): categorized Imported Transaction → exactly one balanced **2-line** Journal Entry per transaction (no batching, no splits). Category side = target Account (04); cash side = Bank Account's new **required 1:1 mapped QBO Account** (from 03 mirror, picker suggests Bank/Asset, any Active allowed; unmapped → transactions blocked+flagged). **Sign rule**: `A<0` (outflow) = Debit category / Credit cash `|A|`; `A>0` (inflow) = Debit cash / Credit category `|A|` — `abs` both sides, opposite `PostingType` → debits=credits by construction, **account-type-agnostic** (transfers/refunds/paydowns need no special case), `A=0` rejected. **Decimal 2dp**, home currency only. JE = **thin entity 1:1 to transaction**, snapshots the two Account `qbo_id`s + amount + Debit/Credit + memo (→ QBO `Description`/`PrivateNote`); **no lines table**; 08's sync fields (`sync_status`/`qbo_id`/`requestid`/`DocNumber`/`posted_at`) attach here. Materialized **at approval** (09); pending discardable via un-approve; posted **immutable**. New schema field: Bank Account gains `qbo_account_id`. Unblocks **08** and **09**.
- [Review and approval UI](issues/09-review-approval-ui.md): the review/approve surface ships as **three user-switchable views over one shared model + one operation set** (Jira/Asana list-vs-board pattern), not a single chosen layout: **Ledger table** (dense grid, state-filter tabs, inline Account picker, checkbox bulk approve/push — the **default**), **Focus queue** (one txn at a time, full Dr/Cr Journal Entry preview + balance proof, keyboard approve), **Pipeline board** (kanban lane per state, per-card or whole-lane advance, permanent Failed lane). Views are presentation only — the state model (`imported→categorized→approved→posted` + `failed`), the four operations (assign/override Account, approve, push, retry), permission checks (07), and transitions live **below** the view layer; a batch is just a loop over 08's single-entry push (no batch path). Approve materializes the balanced JE (06) and is barred for uncategorized; failed always surfaces `last_error`+manual retry in every view; JE preview is a shared element reachable everywhere, foregrounded only in Focus queue. View is a **per-User persisted preference** — recommended one nullable `User.preferred_review_view` ∈ {`table`,`queue`,`board`}, default `table`, outside RBAC (UI only); `ponytail:` `localStorage` is the zero-migration fallback. Prototype (all 3 variants, money path verified balanced/sign-correct): [`09-review-approval-prototype.html`](issues/09-review-approval-prototype.html).

## Out of scope

<!-- ruled beyond the v1 destination; never graduates -->

- **CI/CD pipeline** (GitHub Actions) — infra chore, `/wizard` later, not a spec decision.
- **In-app financial reporting** (P&L, balance sheet) — QuickBooks Online owns reporting.
- **Editing/reversing already-posted entries / full post-export lifecycle** — done in QBO directly.
- **Cross-customer multi-tenancy / SaaS** — see ADR-0001.
- **ML / auto categorization** — deferred; rules-based only.
- **Reading back existing QBO transactions / reconciliation.**
- **Split transactions** (one transaction across multiple category Accounts) — ticket 04 commits one Account per transaction; every Journal Entry is 2 lines (ticket 06).
- **Multi-currency Journal Entries** — v1 assumes each Book's QBO company home currency; no line `CurrencyRef` (ticket 06).
