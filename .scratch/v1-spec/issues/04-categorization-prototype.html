Categorization Rule engine — logic prototype

Question: does this rule model feel right? An Imported Transaction (a bank CSV row) is matched against the Book's ordered Categorization Rules to assign one Account (a QuickBooks ledger account), which becomes the counter-side of its Journal Entry. First-match-wins: rules run in priority order, the first whose conditions all match assigns the Account and evaluation stops. Conditions inside one rule are ANDed — for OR, write two rules. No rule matches → uncategorized, surfaced for a human. A manual override sets the Account directly and beats any rule, even after re-running.
⚑ Design questions to confirm while clicking: (1) amount conditions run on the signed canonical amount (negative = money leaving the account) — intuitive, or match on magnitude? (2) first-match-wins vs. flag-all-conflicts — is a silent priority tiebreak acceptable? (3) should manual override optionally offer "make this a rule"? (deferred by default)
